# Phase 8.1 商业化与分享链路收口设计

**日期：** 2026-08-01  
**状态：** 待评审  
**分支：** `feature/phase-8-commercialization`

## 1. 背景与目标

Phase 8 已具备 subscription、订单、Mock 支付、付费锁态和分享页面的主体结构，但当前实现仍存在影响内测的断点：分享页首次不绘制，小程序码未进入海报，Paywall 忽略来源，订单幂等只记录字段，Mock 支付与权益发放不是一个可恢复的业务操作，以及若干尚未接通的入口会显示虚假成功。

微信支付商户号及小程序支付配置目前尚未具备，因此本批次不接入真实微信支付。目标是先把现有 Phase 8 从“演示闭环”收口为“可控内测闭环”，同时让订单结构便于以后接入 `cloudPay.unifiedOrder` 和 `payNotify`。

## 2. 范围

### 2.1 本批实现

1. 分享页加载完成后自动绘制海报。
2. 云端获取小程序码后上传云存储，前端下载为 Canvas 可用的临时文件。
3. Paywall 读取受控来源并在购买成功后返回对应业务页面。
4. 基于 `openid + client_request_id` 实现订单创建幂等。
5. 将 Mock 支付改造成幂等、可恢复的订单结算流程，避免重复发放权益。
6. 修正注销、家庭档案和空模板订阅等入口的虚假成功反馈。
7. 增加针对以上行为的自动化测试和一次云开发环境验证清单。

### 2.2 明确不做

1. 不接入真实 `cloudPay.unifiedOrder`。
2. 不创建生产 `payNotify` 云函数，但会保留可替换的结算边界。
3. 不实现伴侣邀请、家庭版、月末复盘、服务端订阅消息或管理后台。
4. 不在本批实现 `share_qrcodes` 持久缓存；仅保持返回结构可扩展。
5. 不实施 Phase 9 全量漏斗埋点、城市扩展或 benchmark 校准。
6. 不实现完整账号注销和家庭档案持久化；在对应后端能力完成前，只消除误导性成功提示。

## 3. 设计原则

- **服务端权威：** 订单状态和权益发放由云函数决定，前端不自行推断支付成功。
- **幂等优先：** 创建订单和结算订单都允许安全重试。
- **失败可恢复：** 订单已支付但权益写入失败时，再次结算应继续完成权益，而不是永久拒绝。
- **安全导航：** Paywall 来源使用固定枚举映射，不接受任意 URL。
- **真实反馈：** 未接通能力不得向用户显示“已保存”“已提交”或“已开启”。
- **渐进接入：** Mock 支付和未来微信回调复用同一个服务端结算入口。

## 4. 分享链路设计

### 4.1 服务端

`share.getQrCode` 保持现有鉴权和页面白名单，并在云端模式执行：

1. 调用 `cloud.openapi.wxacode.getUnlimited`。
2. 将返回 Buffer 上传到稳定的云存储路径，例如 `share-qrcodes/landing-v1.png`。
3. 返回：
   - `mode: 'wxacode'`
   - `file_id`
   - `page`
   - `scene`
4. 获取或上传失败时返回 `mode: 'placeholder'`，不让分享页整体失败。

本批不建 `share_qrcodes` 集合。固定 page/scene 的文件允许使用确定性云存储路径覆盖或复用，以避免每次生成随机文件。未来加入多 scene 缓存时，API 字段不变。

### 4.2 前端

分享页初始化顺序：

1. 获取活动方案。
2. 获取小程序码元数据。
3. 如有 `file_id`，调用下载 API 得到本地临时路径并写入 `qrImage`。
4. 刷新 subscription。
5. 等待页面及 Canvas 挂载后调用 `redraw()`。
6. 将 `loading` 设为 `false`。

如果二维码下载失败，仍绘制不带二维码的降级海报，并显示非阻塞提示“二维码暂不可用”。保存图片前继续执行一次 `redraw()`，确保开关状态与导出内容一致。

### 4.3 Canvas 生命周期

首次绘制放在页面完成数据加载后的下一渲染周期，避免 Canvas 尚未挂载。绘制失败写入 `errorMsg`，页面提供“重新生成”动作，而不是保持空白。

## 5. Paywall 回跳设计

### 5.1 来源枚举

Paywall 只识别以下来源值：

- `preview` → `/subpackages/report/preview`
- `full` → `/subpackages/report/full`
- `dashboard` → `/pages/dashboard/index`
- `actions` → `/pages/actions/index`
- `share` → `/subpackages/report/share`
- `pdf` → `/subpackages/report/full`

未知、缺失或非法来源默认 `/subpackages/report/full`。

### 5.2 导航策略

购买成功后使用明确的目标路由刷新已解锁状态。由于来源页可能在不同页面栈、且需要重新触发 `onShow`/数据加载，本批统一使用受控目标的 `reLaunch`，不依赖不稳定的 `navigateBack` 层级。

这会清空页面栈，但行为确定、可测试，并避免返回到过期锁态页面。后续如果需要保留页面栈，可单独优化。

## 6. 订单幂等设计

### 6.1 创建订单

新增 DB 查询能力：按 `openid + client_request_id` 查询订单。

`orders.create` 处理顺序：

1. 校验登录、Owner、SKU、活动方案和已有权益。
2. 要求 `client_request_id` 为非空且满足长度约束。
3. 查询相同 `openid + client_request_id`。
4. 若存在：
   - SKU 与请求一致时返回原订单和对应支付描述。
   - SKU 不一致时返回冲突错误，避免同一幂等键被复用。
5. 若不存在，创建 pending 订单。
6. 数据库增加 `openid + client_request_id` 唯一索引，处理并发竞态。
7. 若插入触发唯一键冲突，重新查询并返回已存在订单。

本地 `memoryStore` 走相同行为，使现有测试能验证语义。

### 6.2 响应裁剪

创建订单响应不再直接返回完整数据库文档，只返回前端所需字段：

- `_id`
- `sku`
- `amount_fen`
- `status`
- `created_at`

支付描述返回：

- `mode: 'mock'`
- `order_id`
- `amount_fen`
- `sku`

为兼容迁移期，可以在同一批同步更新前端，不保留新的双格式长期兼容层。

## 7. Mock 结算与权益一致性设计

### 7.1 结算边界

在 handler 内抽取单一业务函数，例如 `settlePaidOrder`。它接收：

- 订单
- 支付渠道
- 交易号
- 支付时间

Mock action 和未来 `payNotify` 都调用该函数。

### 7.2 状态语义

- `pending`：可以进入结算。
- `paid` 且权益已关联到该订单：直接返回当前订单和权益，视为幂等成功。
- `paid` 但权益缺失或未关联该订单：继续补发权益，视为恢复流程。
- 其他终态：返回明确状态错误。

### 7.3 一致性

云数据库模式优先使用事务完成：

1. 读取并校验订单归属和状态。
2. 标记订单 paid。
3. Upsert subscription，并写入 `source_order_id`。
4. 提交事务。

如果当前云数据库 SDK 对现有封装的事务支持不足，则实现可恢复状态机，并以测试覆盖“订单已 paid、权益未发放”的重试场景。不能继续维持“paid 后永远拒绝重试”的行为。

### 7.4 权益期限

重复结算同一订单不得再次延长权益。期限只在该订单第一次成功关联 subscription 时计算。恢复流程使用原支付时间或订单 `paid_at`，不使用新的重试时间重复累加。

## 8. 未接通入口的真实反馈

### 8.1 订阅提醒

- `tmplIds` 为空时不调用 `requestSubscribeMessage`。
- 显示“提醒服务准备中”，不写入 `subscribe_status`，不提示“已开启提醒”。
- 模板 ID 非空时保留现有授权流程。

### 8.2 家庭档案

本批不实现 `family.update`。保存动作改为明确提示“家庭档案保存功能准备中，当前修改不会同步”，不得修改本地 `original` 后伪装保存成功。页面可以保留编辑交互，用于后续接入。

### 8.3 注销与导出

- 注销确认后提示“在线注销正在接入，当前未提交任何申请”，不显示已提交。
- CSV 和隐私政策入口分别使用准确的“功能准备中”文案。
- PDF 若已有真实可用入口，应导航至真实导出能力；若当前页面无法获得活动方案，则明确说明需从完整报告导出，不伪造成功。

### 8.4 伴侣与家庭版

继续保持“Phase 10 / 敬请期待”，不纳入本批实现。

## 9. 错误处理

- 二维码失败：分享海报降级可用，展示非阻塞提示。
- 首次绘制失败：显示错误和重试按钮。
- 创建订单重复键：重新读取订单并返回，不向用户暴露数据库错误。
- 幂等键复用到不同 SKU：返回业务冲突。
- 结算恢复失败：保留可重试状态，并返回统一用户提示。
- 页面来源非法：忽略并使用默认完整报告路由。
- 未接通入口：准确告知未执行任何持久化或申请操作。

## 10. 测试设计

### 10.1 云函数单元/本地集成测试

新增或扩展商业化测试：

1. 同一 `client_request_id` 重复创建返回同一订单。
2. 相同幂等键配不同 SKU 返回冲突。
3. 并发或模拟唯一键冲突后返回原订单。
4. 同一订单重复 Mock 结算不重复延长权益。
5. paid 但无 subscription 时重试能补发权益。
6. DTO 不暴露内部交易字段。
7. 二维码本地模式返回明确 placeholder。
8. 云端上传逻辑通过依赖桩验证 file_id 响应。

### 10.2 前端测试/可测纯函数

把来源映射抽成纯函数并测试：

- 六个合法来源。
- 缺失来源。
- 非法路径和注入字符串。

对分享页通过组件测试或可替换依赖验证：

- 初始化完成调用首次绘制。
- 有 file_id 时下载并传给 poster。
- 二维码失败仍绘制降级海报。
- 保存前再次绘制。

### 10.3 构建与人工验证

- 执行现有全量测试。
- 执行 `build:mp-weixin`。
- 微信开发者工具验证 Canvas 首绘。
- 云开发环境验证 wxacode 上传和下载。
- 真机扫码验证回到 `pages/landing/index`。
- 从各来源进入 Paywall，购买后验证目标页面和权益刷新。

## 11. 数据与部署变更

1. 为 `orders` 增加 `openid + client_request_id` 唯一索引。
2. 已存在 `client_request_id = null` 的历史 Mock 订单不参与幂等查询；部署脚本需确认云数据库唯一索引对空值的行为。若空值也冲突，则先迁移旧订单或采用非空字段/稀疏索引策略。
3. 云函数需具备 wxacode 和云存储权限。
4. 小程序码固定页面必须已在 `pages.json` 注册并发布到相应环境。
5. 本批不需要商户号配置。

## 12. 验收标准

- 分享页首次进入即可看到已绘制海报。
- 云环境海报包含可扫描且能落到指定页面的小程序码。
- 二维码服务失败时海报仍可生成和保存。
- Paywall 所有合法来源均返回预期页面，非法来源不会任意跳转。
- 相同幂等键只产生一张订单。
- 同一订单重复结算不重复发放或延长权益。
- paid/未发权益的不一致状态可以通过重试恢复。
- 创建订单响应不暴露不必要的内部字段。
- 空模板、家庭档案和注销入口不再显示虚假成功。
- 现有测试与新增测试通过，微信小程序构建通过。
- 云开发环境完成一次 wxacode 与云存储联调记录。

## 13. 后续衔接

Phase 8.1 完成后进入 Phase 9：先实现 `track.batch` 和关键漏斗事件，再进行性能、安全、隐私材料和小范围内测。商户条件具备后，真实支付应复用本设计的订单创建、幂等和结算边界，只替换支付发起与可信回调来源。
